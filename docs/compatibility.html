Verified behavior, not assumptions.

Live SQL Server 2022 integration tests and public-NuGet in-memory examples are different levels of evidence. One passing provider does not imply parity with another. This table deliberately exposes what still needs testing.

VERIFIED IN CI

Named executable assertions

Every row below links to a checked-in executable method. Documentation CI verifies its method name remains present. The published package cookbook runs on every PR; live SQL Server Testcontainers checks verify provider-specific behavior separately. Historical traversals read persisted SQL history and resolve snapshots in memory; they are not translated into a temporal SQL graph query. Edge lifecycle is resolved by persistent edge ID, not merely matching endpoints.

Run the same evidence locally

dotnet run --project samples/Gorm.Cookbook/Gorm.Cookbook.csproj -c Release
dotnet test tests/Gorm.SqlServer.Tests/Gorm.SqlServer.Tests.csproj -c Release

First command: .NET 10 and public NuGet; no Docker or database. Second: Docker and disposable SQL Server 2022, no paid hosting. The browser Playground remains an illustrative JavaScript translator, not live GORM SQL verification.
