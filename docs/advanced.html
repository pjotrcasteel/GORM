ADVANCED CAPABILITIES

One graph runtime, deeper ways to inspect it.

GORM is a graph ORM first. Graph Intelligence, Digital Twin, GraphRAG, Helix and the ChangeSet compiler are deeper capabilities built around the same graph model — not separate products competing with the persistence core.

PUBLIC-SURFACE STATUS

Separate capability direction from published API

The public GORM source includes these advanced capabilities, but the current NuGet package is still a preview. This page describes their intent and boundaries without implying a stable API guarantee.

Publication rule

Validate exact namespaces and method signatures against the published GORM package before using these experimental capabilities; stable compatibility is not guaranteed yet.

GRAPH INTELLIGENCE

Derive insight from the same graph model

Graph Intelligence covers algorithms and projections such as centrality, routing, connected components, communities and impact analysis. The important architectural point is that analysis consumes ordinary GORM graph entities rather than requiring a second domain model.

InputConfigured GORM graph state or a graph projection.
OutputDerived analysis: paths, ranking, components, communities or affected topology.
MutationNone implicitly. Analysis remains read-only until application code explicitly chooses a change.
TEMPORAL DIGITAL TWIN

Rehearse graph scenarios without silently persisting them

Digital-twin capability uses graph state and history to isolate scenarios such as drift, outage rehearsal and what-if analysis. Simulation belongs above persistence: it can reason about possible graph states without turning every scenario into a database mutation.

BoundaryA simulation may propose or expose effects; persistence still requires an explicit application decision.
EXPLAINABLE GRAPHRAG

Ground answers in paths, not only retrieved text

GraphRAG capability can use graph topology to keep evidence path-aware and explain why a piece of information is connected to the question. Authorization and graph scope remain explicit concerns rather than being hidden inside retrieval.

EvidenceGraph-scoped nodes, relationships and paths.
ExplainabilityPreserve the connection between an answer and the graph evidence that supports it.
SecurityAuthorization boundaries remain part of application and query policy.
HELIX

Inspect and reason about graph queries

Helix is the query-analysis capability around GORM. Its documented direction includes generated SQL inspection, query analysis and safe semantics-preserving optimization.

The playground on this site previews the experience we want: application intent on one side, graph/query anatomy in the middle and SQL shape on the other. The website's current JavaScript preview must eventually be replaced by a client-side integration using the actual GORM translator.

CHANGESET & TRANSACTION COMPILER

Make graph writes inspectable before they execute

The ChangeSet capability is intended to order graph persistence work, preserve transaction and rollback semantics and make conflicts understandable. The public source has already separated GORM's change-set capabilities from the independent Forge product family.

Naming gate

The public capability name is ChangeSet & transaction compiler. Consult the current public source and NuGet binary for exact APIs; the advanced surface remains preview quality.

RESPONSIBILITY BOUNDARY

Advanced capability still does not own business policy

GORM mayMap, translate, inspect, analyze, simulate, plan and explain graph persistence mechanics.
Application ownsWhether a proposed mutation is allowed, desirable or should actually be committed.
