GUIDES & COOKBOOK

Start from the problem you need to solve.

These recipes combine the core GORM model and query operators into common graph-persistence tasks.

RECIPE

Find direct dependencies of a service

var dependencies = await context.Set<ServiceNode>()
    .Where(x => x.Id == serviceId)
    .Outgoing<DependsOnEdge, ServiceNode>()
    .ToListAsync();

Use outgoing traversal when the current service is the source of a dependency relation.

TRY ITOpen in playground

Inspect the SQL Server Graph MATCH shape for this traversal.

RECIPE

Find everything that depends on a node

var dependents = await context.Set<ServiceNode>()
    .Where(x => x.Id == databaseId)
    .Incoming<DependsOnEdge, ServiceNode>()
    .ToListAsync();

This is useful for blast-radius and impact questions where the selected node is the target of dependency edges.

RECIPE

Reconstruct topology at incident time

var historicalDependencies = await context.Set<ServiceNode>()
    .AsOf(incidentStartedAt)
    .Where(x => x.Id == serviceId)
    .Outgoing<DependsOnEdge, ServiceNode>()
    .ToListAsync();

Use this pattern when current topology has already changed and you need to understand what was connected when an incident began.

Consistency matters

The meaningful result is a historical graph, not a current edge set joined to historical node rows.

RECIPE

Load a domain object with related graph data

var person = await context.Set<PersonNode>()
    .Include(x => x.Projects)
    .SingleAsync(x => x.Id == personId);

Prefer relationship loading when application code needs the connected object graph rather than a traversal result.

RECIPE

Keep operational queries bounded

var active = await context.Set<ServiceNode>()
    .Where(x => x.State == ServiceState.Active)
    .OrderBy(x => x.Name)
    .Take(100)
    .ToListAsync();

Bounded reads reduce accidental fan-out and make interactive tooling more predictable. Combine them with deterministic ordering.

RECIPE

Test graph behavior without SQL in every test

FAST TEST
var context = CreateInMemoryGraphContext();

SeedGraph(context);

var result = await sut.FindDependencies(id);

Assert.AreEqual(2, result.Count);
PROVIDER TEST
await using var database = await SqlGraphFixture.StartAsync();
var context = database.CreateContext();

// Validate SQL-specific translation,
// temporal and concurrency behavior.

Use the in-memory provider for domain/query behavior and a smaller provider suite for SQL Server-specific semantics.

RECIPE

Analyze impact without mutating the graph

var projection = await graph.ProjectAsync();
var impact = projection.ImpactFrom(serviceId);

foreach (var path in impact.Paths)
{
    // explain why each node is affected
}

Graph Intelligence should consume ordinary GORM graph state and remain read-only until application code explicitly chooses a mutation.

RECIPE

Preview a graph mutation before applying it

var plan = context.ChangeSet.Preview();

foreach (var operation in plan.Operations)
{
    Console.WriteLine(operation);
}

await context.SaveChangesAsync();

The ChangeSet compiler is intended to make ordered graph writes, rollback semantics and conflicts explainable before persistence.

CHOOSING AN API

Traversal, Include, analysis or mutation?

Outgoing / IncomingYou are asking which nodes are connected through a specific path.
Include / ThenIncludeYou want a connected object graph materialized.
Graph IntelligenceYou want derived insight such as impact, centrality or routing.
ChangeSetYou want to inspect or execute graph persistence work.
